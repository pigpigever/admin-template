# Admin Template

A production-ready admin dashboard template built with modern React ecosystem.

## Tech Stack

| Technology | Version | Purpose |
|---|---|---|
| React | 19.x | UI library |
| TypeScript | 5.9+ (7 when released) | Type safety |
| Vite | 6.x | Build tool & dev server |
| Tanstack Router | 1.x | Virtual file routes (type-safe) |
| Tanstack Query | 5.x | Server state & data fetching |
| Ant Design | 6.x | UI component library |
| Ant Design ProComponents | 3.x (beta) | Pro-level admin components (ProTable, ProForm, ProLayout, ProCard) |
| Tailwind CSS | 4.x | Utility-first CSS (via `@tailwindcss/vite`) |
| LinguiJS | 5.x | Internationalization (i18n) |
| es-toolkit | 1.x | Utility functions (prefer over hand-rolled / lodash) |

## Getting Started

```bash
# Install dependencies
npm install

# Start dev server
npm run dev

# Build for production
npm run build

# Preview production build
npm run serve
```

## Features

### Routing (Tanstack Router)
- Virtual file routes declared in `src/routes.ts` (`rootRoute` / `index` / `route`)
- Automatic code splitting with type-safe route parameters and links
- Auto-generated `routeTree.gen.ts` via Vite plugin

### Data Fetching (Tanstack Query)
- Pre-configured QueryClient with sensible defaults
- DevTools enabled in development
- Example usage in Dashboard and Users pages

### UI Components
- **Ant Design v6**: ConfigProvider with theme tokens
- **ProComponents**: ProLayout (admin shell), ProTable (data tables), ProForm (forms), ProCard (cards)
- **Tailwind CSS v4**: Utility classes co-existing with Ant Design

### Internationalization (LinguiJS)
- Two locales: English (`en`) and Chinese (`zh`)
- Language switcher in header
- Ant Design locale auto-syncs with Lingui locale
- dayjs locale syncs automatically

```bash
# Extract messages from source
npm run extract
```

Catalogs are compiled on the fly by `@lingui/vite-plugin` during `dev` and `build`.

### Testing
- Vitest + Testing Library (jsdom); tests live in `tests/` (`*.test.ts(x)`)
- `npm test` (run once) / `npm run test:watch`

### Environment Variables
- Variables are declared once in `helm/values.yaml` (plus per-environment overrides) and rendered into `.env.<mode>` before `dev`/`build` — i.e. build-time injection.
- `src/lib/env.ts` validates them with zod at startup and fails fast on missing/invalid values.

```bash
# Render helm values into .env.<environment>
pnpm env:sync development
```

### Path Aliases
- `@/*` → `src/*`
- `@components/*` → `src/components/*`
- `@layouts/*` → `src/layouts/*`
- `@routes/*` → `src/routes/*`
- `@lib/*` → `src/lib/*`
- `@i18n/*` → `src/i18n/*`
